# Ticket 002 — a forced response ends the turn, queued input waits for the next turn

Upstream: ag2 `3bee17b3c6` (#3639). Decision: D-127. Date: 2026-11-19.

## What was done

- `agent/turn.go` (`turnBody`): the `ResponseForce` check comes first in the tool loop and returns before the
  leftover-input flush. After a forced response the turn makes no further model call; the inbox is kept for the next turn.
- Doc comments updated: `AgentRun.Enqueue`, `Context.SpawnBackground`, `MemoryStream.SpawnBackground` (the exception for
  a turn that ends without another model call).
- `docs/DECISIONS.md` D-127, `docs/MIGRATION.md` §11 (header created here; ticket 001 creates the same section).
- Invariant checked in the other places (details in D-127): `llmTrigger` / `DrainedModelRequest`, AG-UI client path,
  HITL. No code change was needed there, so `agui/stream.go` is untouched.

## Tests

- `agent/forced_turn_test.go`: final tool + queued input; client hand-off + queued input, then resume on the same stream
  (the queued message is the last request, right after the client's result); ordinary reply + queued input (the old
  extra-call behavior stays).
- `agui/forced_turn_test.go`: client hand-off + queued input; final tool + queued input, through the public AG-UI handler.
