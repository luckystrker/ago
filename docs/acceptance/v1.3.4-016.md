# Acceptance report — ticket 016: a write into a departed agent's pipe is `ErrAgentExited`, not `broken pipe`

Product race behind the `acp/TestProviderStartupFailures/exits_during_the_handshake` flake: the agent process ends
right after the handshake starts, the client's `initialize` write lands in a pipe whose reader is gone, and the
caller got `acp: write: write |1: broken pipe` where the contract promises a transport error wrapping
`ErrAgentExited`. No Python-parity question here — the Go sentinel is ours — so no DECISIONS entry (the ticket
reserves none: `decisions: none`) and no MIGRATION section: the public API is unchanged, only the error a dead
agent produces is typed as documented.

Executor: `exec-deepseek-016`. Base: `main` @ `07a3c98`. Toolchain `GOTOOLCHAIN=go1.24.13`, `GOMAXPROCS=2`,
tests `-p 1`, `nice -n 19`. Status stops at `review`.

## What changed

| Step | Change | Files |
|---|---|---|
| 1 | Red test: fake agent closes its stdin, announces it on stdout, exits; the test drains stdout to EOF in `afterStart` so the handshake write provably hits a pipe with no reader | `acp/bridge_test.go` (`TestBridgeAgentGoneBeforeHandshake`, role `acp-leaves-at-once`) |
| 2 | The bridge collects the agent's exit (`Process.Wait`, not `cmd.Wait`) into a channel closed when the process ends | `acp/bridge.go` (`Bridge.exited`, goroutine in `start`) |
| 3 | Every request write goes through `writeRequest`: a pipe error (`syscall.EPIPE` / `os.ErrClosed` / `io.ErrClosedPipe`) waits a bounded 500 ms for that exit and, when the agent is gone, returns `ErrAgentExited` wrapping the write error | `acp/bridge.go` (`writeRequest`, `pipeGone`, `waitExited`), `acp/acp.go` (`exitGrace`, sentinel doc) |
| 4 | The `known-issues` entry moved from "Flaky tests" to "Flakes already fixed" | `docs/known-issues.md` |

**Why `Process.Wait` and not `cmd.Wait`.** `exec.Cmd.Wait` closes the parent's pipe ends after the child exits, and
a reply the agent wrote just before exiting still has to be readable (`readReply` drains stdout to EOF — that path
is what returns `ErrProtocol` + `ErrAgentExited` today). `os.Process.Wait` only reaps the child; the kernel keeps
the buffered stdout readable. `stop()`'s later `cmd.Wait` then loses the race, returns `ErrProcessDone` (ignored)
and still closes the descriptors.

**Bound.** `exitGrace = 500 ms` is a ceiling, not a wait: when stdin's reader disappears the process is normally
gone already, so the channel is closed within a few scheduler hops. An agent that closed stdin and kept running
keeps its own write error (still a transport error through `isTransportErr`, `EPIPE` is reachable via `errors.Is`).
The wait happens outside `writeMu`, so a cancel cannot be held behind it.

**Python parity.** `session/cancel` and request writes keep their shape; only the error of a write that cannot
land is named after the agent's exit. No `// AGO-DEVIATION`.

## Finish line

### 1. Deterministic test: red before, green after

`go test -count=1 -p 1 -run '^TestBridgeAgentGoneBeforeHandshake$' ./acp/`

Before (write path without the exit check) — the exact error the ticket reports, on every run:

```
--- FAIL: TestBridgeAgentGoneBeforeHandshake (0.02s)
    bridge_test.go:427: err = acp: write: write |1: broken pipe, want an error wrapping ErrAgentExited
FAIL	github.com/luckystrker/ago/acp	0.121s
```

After:

```
=== RUN   TestBridgeAgentGoneBeforeHandshake
--- PASS: TestBridgeAgentGoneBeforeHandshake (0.01s)
ok  	github.com/luckystrker/ago/acp	0.033s
```

The ordering is carried by the pipes, not by timing: the fake agent closes stdin *before* it writes `ready` on
stdout, and the test only reaches the handshake write after reading stdout to EOF — i.e. after the process is
gone. No sleeps anywhere.
