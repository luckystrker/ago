# Ticket 008 — agui: held turns released outside the registry lock, отчёт исполнителя

Status: **review** (исполнитель `exec-sonnet008`, база `main` @ `c0e031c`). Отступления от Python нет,
записи DECISIONS нет (D-132 не нужен): правка приводит `release()` к Python-семантике.

## Корень

В Python две операции (`ag2/ag_ui/interrupts.py` @ v1.3.2, `ServedTurn`): `release()` = `task.cancel()`,
не ждёт; `aclose()` = `release()` + `gather`, ждёт размотку. В AGo `release()` делал обе: закрывал run
(`run.Close()` → `awaitTurn`) и ждал. Отсюда два симптома: дедлок под `servedTurns.mu` (сворачивающийся ход
берёт ту же блокировку в `discard`) и само-вытеснение, где спрашивающий ход ждал собственный таймаут вопроса.

## Что сделано

- `agui/interrupts.go`:
  - `servedTurn.release()` — только отмена: закрывает `abandon` вопроса и запускает `run.Close()` на своей
    горутине (поле `closed` закрывается, когда run свернулся). Не ждёт.
  - `servedTurn.aclose()` — `release()` + ожидание `closed` (аналог Python `aclose`).
  - `evictExpiredLocked` возвращает вынутых из `held` жертв; `hold` (вытеснение того же треда, `MaxHeld`),
    `take`, `holds` собирают жертв под `st.mu` и зовут `releaseAfterUnlock` после `Unlock`.
  - `releaseAll`: сначала `release` всем, затем `aclose` всем (остановка сервера ждёт размотку, как Python `gather`).
  - `askClient`: `t.out.hold()` (пауза вывода) теперь **до** `turns.hold`. Если жертва — сам спрашивающий ход,
    его отмена уже идёт, и драйвер, дойдя до `Result`, должен застать вывод на паузе (`isPaused`), а не писать
    «cancelled» в обмен. Порядок событий для клиента не меняется: пауза только откладывает отправку до `pause()`.
- `agui/server.go:223` (`resume`, ветка «просрочен»): добавлен `t.release()` после `discard`; комментарий переписан (паритет `resume_held_turn`).
- `agui/server.go:291` (`abandon`): `release()` → `aclose()` (Python `_cancel` делает `await turn.aclose()`).
- `agui/release_locking_test.go` (новый): 8 тестов, публичный handler + `httptest`.
- `docs/known-issues.md`: строка добавлена до правки, после правки перенесена в новый раздел «Defects fixed».

## Все вызовы `release`/`Close`: было → стало

| Вызов | Было | Стало | Почему |
|---|---|---|---|
| `hold`: вытеснение прежнего хода того же треда (было `:464`) | ждал, под `st.mu` | не ждёт, после `Unlock` | ждать нечего: жертва уже вынута из `held`, у нового хода свой run и свой stream; дедлок |
| `hold`: цикл `MaxHeld` (было `:477`) | ждал, под `st.mu` | не ждёт, после `Unlock`; жертва может быть самим спрашивающим | то же; плюс ход не может ждать сам себя |
| `evictExpiredLocked` (было `:586`; через `hold`, `take`, `holds`) | ждал, под `st.mu` | возвращает жертв; не ждёт, после `Unlock` | то же; ответ запросу не зависит от размотки чужого хода |
| `releaseAll` / `Server.Close` | ждал, после `Unlock` | **ждёт** (`aclose`), тест | остановка сервера обязана дождаться очистки ходов; ходы-жертвы, ещё лежащие в `byStream`, тоже попадают в список |
| `server.go:291` `abandon` (cancelled resume) | ждал | **ждёт** (`aclose`), тест | `Closings()` и `out.abandon()` берутся у остановившегося хода; ответ клиенту после размотки (Python `_cancel`) |
| `server.go:336/349/361` `begin`: `run.Close()` при ошибке старта | ждал | не менялось (ждёт) | run без драйвера, ни одна блокировка реестра не держится |
| `serve.go:90` `defer run.Close()` | ждал | не менялось | не связан с реестром, run своего запроса |
| `resume`, ветка «неизвестен / уже отвечен / просрочен» (`server.go:219`) | только `discard`, ход оставался припаркованным до своего таймера | `discard` + `release()` (не ждёт, реестр не заблокирован), тест | Python `resume_held_turn` в этой ветке зовёт `turn.release()`; `discard` без `release` был неполным паритетом: вопрос уже нельзя принять, а ход и его run жили до таймаута вопроса (до часа TTL), держа горутины и запись в `byStream` |
| `discard` | не release | не менялось | только снимает из `held`/`byStream`; сам ход не останавливает |

Ожидание, которое было нужным, сохранено ожидающим вариантом и покрыто тестом: остановка сервера
(`TestServerCloseWaitsForHeldTurnsToUnwind`) и cancelled resume (`TestServerCancelledResumeWaitsForTurnToUnwind`).
Не-ждущая отмена не теряет ход: каждый тест вытеснения ждёт `closed` и `driverDone` с дедлайном (`awaitUnwound`).
