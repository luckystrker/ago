# Gap audit: AG2 v1.3.0 vs AGo (2026-11-09)

A full inventory of AG2 v1.3.0 functionality that AGo does not cover, or covers only in part.

**Method.** Five research agents (Claude Haiku) each compared one slice of `ag2/ag2/` (tag
`v1.3.0`, `1229064a`) with the Go tree, class by class. Each agent cross-checked its
findings against `docs/PORT_STATUS.md`, `docs/DECISIONS.md` and `docs/MIGRATION.md`. Each item
is marked:

- `MISSING`: absent from AGo.
- `PARTIAL`: some of the item is missing.
- `UNRECORDED`: no decision record covers the gap.
- `DEFERRED D-xxx`: a recorded deferral.
- `OUT-OF-SCOPE D-xxx`: closed by design.

COVERED items are not listed.

**Verification.** The orchestrator checked 12 claims against the code by hand, across every
slice, and all 12 held. Examples: Anthropic has no `thinking` request knob; no provider has
`tool_choice`; there is no `extra_body` outside Decisions and no injectable `*http.Client`;
the network `Envelope` has no `task_id` or `trace_id`; the hub has no `Auth*` or `Health`;
the eval package has no `no_tool_errors`; AG-UI parses `RunAgentInput.tools` but never
registers them; `stream.SubscribeOptions` has no timeout; `RetryMiddleware` has no
`retry_on`; there is no `TailWindowCompact`; there is no `ACPConfig` model provider. The
reports remain model output, so every executor must re-confirm a gap in code before
implementing it.

**Totals.** 292 items: 129 UNRECORDED, 155 DEFERRED, 7 OUT-OF-SCOPE.

**Record defects found by the audit.** Each is fixed together with the wave that touches the
area.

- `docs/MIGRATION.md` (`acp/` row) lists `ACPClient` as ported. Python `ACPClient` and
  `ACPConfig` (`ag2/acp/config.py:56`) are an LLM *provider* that drives an ACP agent such as
  Claude Code, Codex, OpenCode or KiloCode. That provider is not in AGo.
- `docs/PORT_STATUS.md` (`extensions/` row) calls `extensions/` "Python infrastructure".
  It is not: all eight subpackages are runtime features (search providers, sandboxes, NLIP,
  governance middleware, compaction verifier, failure attribution).

Record problems found while auditing (these matter more than the counts):
1. `docs/MIGRATION.md:280` lists `ACPClient (client.py:77)` as ported. It is not: the ACP-as-LLM-provider adapter is absent (gap 26), and no D-record covers it.
2. `docs/PORT_STATUS.md` mcpserver row says "DNS-rebinding protection" is not ported. D-078 added `AllowedHosts`, `AllowedOrigins` and `Authorize`, so that row is stale. OAuth metadata and bearer checks are still missing.
3. D-072 lists `STTTranslationConfig` under the realtime-websocket stack. It is a plain HTTP call and could be done now (gap 56).
4. D-067 defers card JWS signing on the grounds that the stdlib has no JWS. The stdlib does have `crypto/ed25519`, `crypto/ecdsa`, `crypto/rsa` and `crypto/hmac`; the real cost is the canonical card form and key handling. Worth re-deciding.
5. D-057 / D-072 group turn detection with the websocket stack. `SilenceTurnDetector` is pure logic and needs no dependency (gap 60).
6. Variant runs (gap 65), `no_tool_errors` (gap 70), the console reporter (gap 68) and the human pairwise flow (gap 67) are not in any D-record ledger.
7. MIGRATION.md:209 says MCP sampling is "not ported" with no D-record. The consume-side answering that D-029 defers is the same family.

Five most valuable gaps:
1. **ACP as an LLM provider** (`ACPConfig` / `ACPClient` plus the `ClaudeCode`, `Codex`, `OpenCode`, `KiloCode` presets) — status: PARTIAL, record: UNRECORDED, size: L. The Bridge already speaks the wire; the missing piece is the adapter and the presets. This lets an agent use a coding CLI as its model, and the docs wrongly say it exists.
2. **A2A conversational client as a model** (`A2AConfig` ModelConfig, history shipping, polling, reconnect) — status: PARTIAL, record: DEFERRED D-049, size: L. The most common cross-agent path after the server; the client drivers exist but the model adapter does not.
3. **AG-UI frontend tools** (`RunAgentInput.tools` registered per turn) — status: MISSING, record: UNRECORDED, size: M. Without it a CopilotKit-style front end cannot expose its own tools; `NewClientTool` already exists and is unused.
4. **MCP served-agent elicitation** (`context.input()` routed to the client as `elicitation/create`) — status: MISSING, record: UNRECORDED, size: M. This is the human-approval path for MCP-served agents. It needs an SSE back-channel that D-058 does not serve yet, so the SSE answer path comes first.
5. **Eval variants and run-level pairwise** (`run_variants` leaderboard, `run_pairwise` / `evaluate_pairwise`) — status: MISSING / PARTIAL, record: UNRECORDED, size: L / M. This is the comparison machinery for choosing between prompts or models, and it is absent from every ledger. Card JWS signing (A2A) is the strongest honourable mention, because its deferral rests on an overstated rationale.
