## 1. ACP: миграция на agent-client-protocol 1.0 (`3b5bd7d122`)

Сама миграция SDK к нам неприменима: `acp/*.go` работает на stdlib и newline-JSON-RPC, без SDK.
Проверялись только поведения, которые коммит поменял.

### 1a. `session/new`: абсолютные пути

**Python.** Клиент резолвит оба поля перед отправкой:
`ag2/acp/client.py:145` `cwd=str(Path(self.config.cwd).resolve())`,
`ag2/acp/client.py:148` `additional_directories=[str(Path(d).resolve()) for d in self.config.additional_directories]`.
Сервер ничего не проверяет: `ag2/acp/agent.py:385-406` (`new_session`) записывает `cwd` как контекст.
Схема SDK 1.0.0 тоже не проверяет: `cwd: str` с docstring «Must be an absolute path»
(`/tmp/agent_client_protocol-1.0.0/src/acp/schema.py:4455-4467`, та же формулировка у
`LoadSessionRequest` — `3724-3738`). То есть требование
абсолютности — обязанность **клиента**, и Python её исполняет.

**Наше.**
`cwd` — `acp/provider.go:363-372` (`Config.cwd()`: `filepath.Abs`, `"."` → абсолютный).
`additionalDirectories` — `acp/provider_start.go:98` передаёт `c.AdditionalDirectories` **как заданы**;
`acp/provider.go:152-153` документирует поле как «extra ACP workspace roots», без нормализации.
Низкоуровневый `Bridge.SessionNew(cwd)` (`acp/bridge.go:276-278`) тоже отправляет без нормализации — это
паритет: Python `ACPSession.ensure` (`ag2/acp/session.py:149,191`) делает так же.

**Доказательство** (`probe`, поведение `messages`; полный вывод — §4):

```
session/new params on the wire: {"cwd":"/home/.../probe/work","additionalDirectories":["extra/one","./extra/two"]}
```

`cwd` абсолютный — паритет. Дополнительные каталоги относительные — Python отправил бы
`["/home/.../extra/one","/home/.../extra/two"]`.

Побочно: `filepath.Abs` не разворачивает симлинки, `Path.resolve()` разворачивает. На смысл
«абсолютный путь» не влияет, на сравнение путей агентом — может.

**Вердикт: дефект** (только `additionalDirectories`; `cwd` — нет).

**Тикет ACP-1 (S).** Резолвить `AdditionalDirectories` там же, где `cwd` (`acp/provider.go:363`,
рядом с `Config.cwd()` — например, `Config.workspace()`), прокинуть в `acp/provider_start.go:98`.
Заденет: `acp/provider.go`, `acp/provider_start.go`, `acp/provider_test.go` (тест на провод:
относительный вход → абсолютные в `session/new`), `docs/PORT_STATUS.md` (строка `acp/`). Запись в
DECISIONS не нужна — это возврат к паритету, а не отступление. Ноль внешних зависимостей.

### 1b. Группировка `agent_message_chunk` по `message_id`

**Python.** `BridgeState` копит не строку, а список сообщений:
`ag2/acp/bridge.py:158,195-196` (`_turn_messages`, `turn_messages`), `ag2/acp/bridge.py:213-232`
(`handle_update`: чанк с новым `message_id` закрывает предыдущее сообщение, отправив `ModelMessage`),
`ag2/acp/bridge.py:235-256` (`_add_message_text`: чанк без id продолжает текущее сообщение; пустой
текст не открывает новое). Ответ хода — **последнее** сообщение, а не склейка:
`ag2/acp/client.py:236-246`. Тесты:
`test/acp/test_client_e2e.py:155` (`test_chunks_of_one_message_make_one_message` — один `ModelMessage`),
`:171` (`test_messages_the_agent_names_apart_are_not_run_together` — `["Let me check.", "Done: it works."]`,
`result.body == "Done: it works."`), `:192` (`test_each_message_is_closed_before_the_next_one_streams`).

**Наше.** `acp/bridge.go:440,458`: `var chunks []string` → `strings.Join(chunks, "")`; `message_id`
игнорируется (`acp/bridge.go:596-600` кладёт `u.Update.text()` в тот же срез), `turnState.text` —
`strings.Builder` (`acp/provider_session.go:43,121`), в ответ уходит одна `ModelMessage`
(`acp/provider_client.go:97-119`).

**Доказательство** (поведение `messages`: чанки `m1 "Let me check."`, `m2 "Done: "`, `m2 "it works."`):

```
reply.Body() = "Let me check.Done: it works."
event ModelMessageChunk "Let me check."
event ModelMessageChunk "Done: "
event ModelMessageChunk "it works."
```

Тот же вход через сам `Bridge` (`./probe bridge`, поведение `messages`):

```
OnUpdate kind="agent_message_chunk" messageId="m1" text="Let me check." bytes=0
OnUpdate kind="agent_message_chunk" messageId="m2" text="Done: " bytes=0
OnUpdate kind="agent_message_chunk" messageId="m2" text="it works." bytes=0
PromptTurn.Text = "Let me check.Done: it works." stop=end_turn
```

`messageId` декодируется и виден в `OnUpdate` — граница есть на входе и теряется на выходе.
Python на этом же входе: два `ModelMessage` (`"Let me check."`, `"Done: it works."`) и
`result.body == "Done: it works."`. Второе следствие: в `ModelResponse` уходит склейка.

**Вердикт: дефект.** Задевает: ответ пользователю (лишняя преамбула в ответе), историю следующего хода
(один ассистентский месседж вместо двух), стриминг UI (одна длинная строка).

**Тикет ACP-2 (S).** Дешёвый вариант — в `providerSession.onUpdate`: держать `currentMessageID` и
`messages []string`, при смене id отправлять `events.ModelMessage` в `conv`, ответ брать из последнего
(симметрично Python). Провод менять не надо: `MessageID` уже декодируется в `Update`
(`acp/acp.go:244`). Дорогой — добавить `TurnResult.Messages` и группировку в `Bridge` (API меняется,
`Prompt`/`PromptTurn` задеты). Рекомендую дешёвый. Заденет: `acp/provider_session.go`,
`acp/provider_client.go` (ответ), `acp/provider_test.go` (три теста из Python плюс пустой чанк не
открывает новое сообщение),
`docs/PORT_STATUS.md`. Не трогает `Bridge` — публичный API пакета остаётся.

### 1c. Блоки промпта и ответа: uri-only image, пустой текст, пустое аудио

**Python.** Одна функция решает, что читается как текст: `ag2/acp/mappers.py:85-102`
(`_textual_block_text`: text, текст встроенного ресурса, `resource_link`), `:61-72` (`block_text`:
плюс `"[image] <uri>"` для image без байт — `_image_uri`, `:75-83`), `:104-118` (`block_to_files`:
image/audio без `data` → `[]`, встроенный blob → файл, `:121-129` `_embedded_blob`), `:138-151`
(`_tool_call_result`: части по одному content-item, пустой текст не создаёт часть; если частей нет —
`ToolResult(status)`), `:230-263` (`block_to_input`), `:265-279` (`prompt_to_inputs`).
Тесты: `test/acp/test_client_e2e.py:122` (`test_a_tool_result_with_only_empty_text_reports_its_status`,
ожидание `[ToolResult("completed")]`), `:536` (`test_an_image_that_only_points_at_a_uri_is_its_link_not_a_file`,
`body == "[image] https://example.com/chart.png"`, `files == []`), `:566`
(`test_an_audio_block_with_no_data_is_not_a_file`, `body == "listen"`, `files == []`).

Функций `blockToInput`/`blockToFiles` в Go нет: их роль делят декодер блока (`contentBlock`,
`Update.UnmarshalJSON`), сбор ответа (`providerSession.onUpdate`) и разбор промпта (`blocksText`).

**Наше.** `acp/acp.go:157-166` — `contentBlock` знает только `text`/`data`/`mimeType` (нет `uri`,
нет `resource`); `acp/acp.go:383-400` — чанк декодирует текст и, при непустых байтах, image/audio;
`acp/provider_session.go:119-131` — текст в `turnState.text`, байты в `Files`, пустой текст → `return`
без события.

**Доказательства** (`probe`):

- `uri-image` — image без байт, с `uri`:
  ```
  reply.Body() = "see the chart"
  reply.Response().Files = 0
  event ModelMessageChunk "see the chart"
  ```
  Python: `"see the chart[image] https://example.com/chart.png"`. Блок исчезает целиком.
  На уровне декодера то же (`./probe bridge`, поведение `uri-image`): блок с `uri` и пустыми
  байтами даёт пустой текст и 0 байт —
  ```
  OnUpdate kind="agent_message_chunk" messageId="" text="" bytes=0
  ```
  **Дефект (ACP-3).**
- `tool-empty-text` — `tool_call_update` с content `[{"type":"content","content":{"type":"text","text":""}}]`
  и `status: "completed"`:
  ```
  event BuiltinToolResultEvent t1 parts=[text="completed"]
  ```
  Совпадает с Python (`ToolResult("completed")`). **Нет дефекта.** (Наш код подставляет статус при
  пустом `ContentText` — `acp/provider_session.go:146-155`.)
  Наблюдение, не блокирует: Python собирает результат **по одной части на content-item**
  (`_tool_call_result`, `ag2/acp/mappers.py:138-151`), мы склеиваем весь текст в один `ContentText`
  (`acp/acp.go:401-408`) и отдаём один `TextInput` (`acp/provider_session.go:148-155`). На пустом
  тексте разницы нет; на двух непустых items — одна часть `"ab"` вместо двух `["a","b"]`.
- `empty-audio` — audio с `data:""`:
  ```
  reply.Body() = "listen"
  reply.Response().Files = 0
  ```
  Совпадает с Python. **Нет дефекта.**
- `resource` (рядом с пунктом, тот же корень) — `{"type":"resource","resource":{"uri":...,"text":"notes body"}}`
  и blob-ресурс:
  ```
  reply.Body() = "see the file"
  reply.Response().Files = 0
  ```
  Python: текст ресурса попал бы в ответ, blob — в `Files`. **Дефект** (клиентская половина ACP-3).

**Serve-сторона — отдельный разбор, и capabilities здесь решают.** Свой `initialize` объявляет
`promptCapabilities{image:false, audio:false, embeddedContext:false}` (`acp/serve.go:542-545`,
закреплено тестом `acp/serve_test.go:242`), Python — `image=true`, `audio=false`,
`embedded_context=true` (`ag2/acp/agent.py:92-94`, отдаётся в `:356-360`). Отсюда:

- `image`, `audio` и `resource` (embedded context) конформный клиент нам не пришлёт — мы честно
  сказали, что не умеем. Их потеря не дефект, а следствие более узких объявленных возможностей
  (записано в PORT_STATUS как «non-text prompt parts»).
- `resource_link` не гейтится **ни одной** capability: `embeddedContext` в схеме описывает только
  `ContentBlock::Resource` (`schema.py:668-684`). Такой блок конформный клиент вправе прислать уже
  сейчас — и он теряется. Это дефект при наших же объявленных capabilities.
- Расхождение с Python по самим возможностям всё равно остаётся: агент на Python принимает картинки и
  встроенный контекст, наш — нет, хотя `prompt_to_inputs` у Python умеет и то, и другое.

Доказательство (`serve_driver.py`): промпт из text + image(uri) + audio(пустой) + resource(text) +
`resource_link` дошёл до хендлера как `userText="hi"` — все четыре блока, включая ссылку, потеряны.
Причина одна: `blocksText` (`acp/acp.go:170-178`) читает только `type:"text"`, а в `contentBlock` нет
полей ни для ссылки, ни для ресурса.

**Вердикт.** Клиент (ответ агента): **дефект** — uri-only image и `resource`/`resource_link`
теряются. Serve: **дефект только для `resource_link`**; потеря `image`/`audio`/`resource` там —
следствие сознательно суженных capability (отступление записано). Пустой tool-текст и пустое
аудио — **нет дефекта**.

**Тикет ACP-3 — две независимые половины, обе S.**

*Клиент (S, обязательная).* Расширить `contentBlock` полями `URI` и
`Resource{URI, Text, Blob, MimeType}`, `Name`/`Title` для `resource_link`; `Update.UnmarshalJSON` —
читать их; `blockText`-эквивалент (~15 строк) для `"[image] <uri>"`, текста ресурса и
`"[resource] <label> (<uri>)"`; `provider_session.onUpdate` — текст в `turnState.text`, blob в `Files`.
Заденет: `acp/acp.go`, `acp/provider_session.go`, `acp/provider_test.go`, `acp/acp_test.go`,
`docs/PORT_STATUS.md`.

*Serve (S, на выбор владельца) — два варианта:*
(а) **только `resource_link`**: объявляемые capabilities не менять, в разборе промпта читать
`resource_link` как текст `"[resource] <name> (<uri>)"` (как `block_to_input` для ссылок). Ничего
сверх объявленного не обещает; закрывает единственную потерю, которую наш собственный контракт не
оправдывает.
(б) **как Python**: объявить `image=true`, `embeddedContext=true` и отдавать `image`/`resource` входами
(image с байтами → ImageInput, uri-only → текст-ссылка, текст ресурса → текст, blob → документ).
Объявление — обещание, поэтому принимать блок надо по-настоящему. Заденет `acp/serve_test.go:242`
(ожидание all-false), `acp/serve.go`, `docs/PORT_STATUS.md`, `docs/DECISIONS.md` (сужение D-052/D-105).

### 1d. Что из списка коммита видно на нашем проводе

запрос `mcp/connect` и уведомление `mcp/notify` посреди хода):

```
reply.Body() = "after mcp methods"
```

Ответ на запрос есть, на уведомление — нет, ход завершился. **Вердикт: нет дефекта.**

**1d.3 `EnvVarAuthMethod` убран из `AuthMethod`.** Python: `ag2/acp/auth.py:44`
(`AuthMethod = TerminalAuthMethod | AuthMethodAgent`), в схеме 1.0.0 класса `EnvVarAuthMethod` больше нет.
Наше: `acp/auth.go:48,84` — вид `"env_var"` моделируется и попадает в `initialize`
(`acp/serve.go:560`). Вопрос был: ломает ли это 1.0-клиента.

Проверено настоящей схемой 1.0.0 из PyPI (не по памяти): `InitializeResponse` объявляет
`auth_methods: Optional[List[Union[TerminalAuthMethod, AuthMethodAgent]]]` (`schema.py:5707`), union
**недискриминированный**, а `AuthMethodAgent` (`schema.py:998-1016`) не имеет литерала `type` и
лишние поля игнорирует. Значит `"type":"env_var"` разбирается как agent-метод: без ошибки, но и без
`vars` (клиент не узнаёт, какие переменные выставить). Вывод прогона:

```
initialize response (raw):
{... "authMethods": [{"id":"token",...},{"id":"env","name":"API key in the environment","type":"env_var","vars":[{"name":"OPENAI_API_KEY","secret":true}]}], "protocolVersion": 1}}
agent-client-protocol 1.0.0 InitializeResponse validation: OK
```

**Вердикт: неучтённое расхождение.** Дефектом провода это не является — 1.0-клиент не падает, — но
и сознательным отступлением назвать нельзя: решение про потерю вида в 1.0 нигде не записано. В

смоделированы») после 1.0 тоже неверен: вида больше нет в union. Пока решение не записано,

По `git show 3399e3ef2e --stat`: новый `ag2/mcp/_document_scripts.py` (+381), `ag2/mcp/apps.py`

### Детектор `<script>`-импортов без `golang.org/x/net/html`

Задача: по телу документа решить три вещи — (1) запускаемый скрипт грузит
`@modelcontextprotocol/ext-apps` (`src`, `import`, `from`, `import()`), либо в его коде есть строка
`"ui/initialize"`; (2) код обращается к `ag2ui`; (3) код сам определяет `window.ag2ui`. Решение
принимается **только по тому, что браузер исполнит**: комментарии, инертные элементы, значения
атрибутов, data-скрипты и строки/комментарии внутри JS не считаются.

Предлагаемая форма (два прохода, оба потоковые):

1. **HTML-сканер** (свой, ~200 строк): идём по байтам; на `<`:
   - `<!--` → до `-->` (комментарий не разбирается);
   - `<!DOCTYPE …>` и прочие `<!…` → до `>`; `<![CDATA[` → до `]]>`. Проверено на CPython 3.13.5:
     `HTMLParser` отдаёт всё между `<![CDATA[` и `]]>` одной unknown-declaration, поэтому `<script>`
     внутри такого раздела Python не видит;
   - **известное расхождение с браузером** (наследуем ради паритета): в HTML-контенте браузер
     закрывает `<![CDATA[` как bogus comment на первом `>`, то есть
     `<![CDATA[x><script>…ui/initialize…</script>]]>` у него скрипт исполнит, а порт (как и Python) —
     нет, и такой документ получит `ag2ui` поверх собственного handshake. Лечится
     `inject_runtime=false` (escape hatch ADR 0037);
   - `</` → имя элемента, закрыть из стека инертных/`script`;
   - иначе — имя тега, затем атрибуты: имя, `=`, значение в `"…"`, `'…'` или без кавычек до пробела/`>`;
     **внутри значения `<` не начинает тег** (главная ловушка: `<div title="<script>…">`);
   - для `script` в нормальном контексте: запомнить `src`, `type`/`language`/`nomodule`, затем
     **raw-text**: тело до первого `</script` (без учёта регистра) — JS-строки и комментарии
     разметку не открывают, `</script>` внутри JS-строки всё равно закрывает элемент (так делает
     браузер и `html.parser`); незакрытый `script` тянется до конца документа;
   - для инертных (`template`, `noscript`, `textarea`, `title`, `style`, `xmp`, `iframe`, `noembed`,
     `noframes`, `plaintext`) — стек предков, содержимое не разбирается как разметка, но `script`
     внутри поглощается целиком; вложенный `template` закрывается своим `</template>`;
   - `on*`-атрибуты у неинертных элементов — тоже «запускаемый код» (Python так делает);
   - `script` запускается, если `type` пуст/`module`/JS-MIME (регэксп Python `:52-54`), либо без
     `type` есть `language` → `text/<language>`; `nomodule` у classic-скрипта — не запускается.
2. **JS-токенайзер** (~150 строк) по телу каждого запускаемого скрипта: пропускать `//…`, `/*…*/`;
   строки `'…'`/`"…"` с `\`-escape; шаблонные литералы с `${…}` (вложенность считать); регулярные
   литералы отличать от деления по предыдущему токену (+ правило «после `)` условия `if/while/for/with`
   `/` открывает регулярку»). Затем — те же три проверки, что в Python: строка `ui/initialize`; строка,
   содержащая пакет, в позиции `from`/`import`/`import(`; обращения к `ag2ui` (не `x.ag2ui`), в том
   числе `window|globalThis|self` + `.ag2ui` / `["ag2ui"]`; определение — `window.ag2ui =` (не `==`).

Ловушки, которые надо закрыть тестами (каждая — реальный провал regex-подхода из ADR 0037):

- `<script>` внутри значения атрибута, внутри `<style>/<title>/<textarea>`, внутри `<template>`
  (в том числе вложенного) и `<noscript>`;
- закомментированный `<script src=…ext-apps…>` в HTML-комментарии;
- `<!--` и `-->` **внутри** JS-строки (`var html = "<!-- not a comment -->"`) — не путать с
  HTML-комментарием;
- `//`-комментарий и `/* … */`, содержащие `import … ext-apps` и `"ui/initialize"`;
- строка `"import { App } from '@modelcontextprotocol/ext-apps'"` внутри `console.log` — это данные,
  не импорт;
- `/` как регулярка после `)` условия: `if (ready) /'/.test(name);` — иначе токенайзер съест код до
  конца строки;
- шаблонный литерал с вложенным шаблоном и `` ` `` внутри `${}`;
- `/[/]/g` (слэш в классе символов регулярки);
- `import(\`…ext-apps…\`)` и `import(\`…ext-apps@${version}\`)`;
- незакрытый `<script>` до конца документа;
- `type="application/json"` (data-скрипт) и `language="vbscript"` — не запускаются;
- `nomodule` у classic-скрипта;
- `<script/>` — в HTML **не** самозакрывающийся;
- документ, который и делает handshake, и зовёт `ag2ui` без определения → инъекция + предупреждение;
- `window["ag2ui"]` vs `other.ag2ui` vs `window.ag2ui == x`;
- `<![CDATA[x><script>var M={initialize:'ui/initialize'};</script>]]>` — раздел до `]]>`, скрипт
  внутри не виден → **с** инъекцией (паритет с Python; браузер поступил бы иначе, см. выше);
- `<svg><script>var M={initialize:'ui/initialize'};</script></svg>` — foreign content: скрипт
  **запускается**, ждём «без инъекции»; ловушка — в регистре тегов и в настоящем CDATA рядом.

Известные границы (записать в комментарии и ADR-копии): `svg`/`math` (foreign content: регистр,
CDATA, `<script>` в SVG), script-data double-escaped state (`<!--<script>` внутри classic-скрипта),
имя метода, собранное в рантайме, алиас в import-map. Для них — `inject_runtime=false` (escape hatch),
как в ADR 0037. Полный HTML/JS-парсер не нужен и не тянет зависимость.

## 3. tealtiger: kill switch в ENFORCE (`a8195adf81`)

Модуль `ag2/extensions/tealtiger` в AGo не портирован (PORT_STATUS: «Not ported, the owner has not
chosen it»), поэтому в коде править нечего — фиксируется поведение и тест, которые надо перенести
вместе с портом.

**До (v1.3.2^, `ag2/extensions/tealtiger/middleware.py:311-347`, ветка ENFORCE — `:343-349`).** В `on_turn` при замороженном агенте
в режиме ENFORCE возвращался `ToolErrorEvent.from_call(event, error=Exception(...))`. Но `event` в
`on_turn` — это `BaseEvent` хода, на практике `ModelRequest` (`ag2/middleware/base.py:92`
`AgentTurn = Callable[[BaseEvent, Context], Awaitable[ModelResponse]]`; у `ModelRequest` полей `id`
нет — `ag2/events/input_events.py:39-43`). `ToolErrorEvent.from_call` (`ag2/events/tool_events.py:172-186`)
читает `call.id` → **`AttributeError: 'ModelRequest' object has no attribute 'id'`**. То есть
kill switch в самом строгом режиме не блокировал ход, а падал.

**После (`middleware.py:311-352`).** Возвращается `ModelResponse(message=ModelMessage(content=...))` —
ход не доходит до модели, пользователь получает дословно:

```
[GOVERNANCE DENIED] Agent '<agent_name>' is frozen (kill switch active). All actions blocked.
```

Решение `GovernanceDecision(action="DENY", reason_codes=["AGENT_FROZEN"], risk_score=100)` пишется в
`decisions` (и в `on_decision`) **до** возврата; MONITOR по-прежнему пропускает ход, записав решение;
OBSERVE не оценивает. Заодно убран мёртвый `is_error = isinstance(result, ToolErrorEvent)` в
`_scan_result` (проверка перенесена к месту использования) — поведение не изменилось.

**Python-тест, который надо перенести вместе с портом:**
`test/extensions/tealtiger/test_governance_middleware.py:496-511`, класс `TestOnTurn`,
`test_frozen_agent_blocked_enforce`: собирает `Agent("assistant", config=TestConfig("model reply"),
middleware=[mw])`, морозит `"assistant"`, делает `ask("hello")` и требует ровно три вещи — тело
ответа равно строке выше, `len(mw.decisions) == 1`, `decisions[0].action == "DENY"` и
`"AGENT_FROZEN" in decisions[0].reason_codes`. Соседний `test_frozen_agent_allowed_monitor` (`:513-…`)
фиксирует, что MONITOR пропускает ход.

**Что это значит для Go-порта.** Наш хук типизирован:
`middleware/middleware.go:18` `type TurnFunc func(ev *events.ModelRequest, ctx *agocontext.Context) (*events.ModelResponse, error)`
и `middleware.go:37` `OnTurn(next TurnFunc, ev *events.ModelRequest, …) (*events.ModelResponse, error)`.
Вернуть `ToolErrorEvent` из `OnTurn` невозможно по типу — компилятор не даст воспроизвести баг.
Поэтому при порте: `OnTurn` возвращает `&events.ModelResponse{Message: &events.ModelMessage{Content: denial}}`
(плюс запись решения в состояние middleware), тест — три проверки выше. Отдельного тикета на сам
багфикс не нужно; это пункт в тикете порта tealtiger, когда владелец его выберет.
