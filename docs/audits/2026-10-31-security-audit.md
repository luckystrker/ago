# Аудит безопасности AGo — 31.10.2026 (v2)

**Версия кода:** v0.7.0 (commit `991a3c0`, ветка main)
**Ревизия отчёта:** v2 — после повторной проверки владельцем и сверки контр-замечаний по коду (все поправки v2 подтверждены чтением исходников; список изменений — в разделе «История ревизий»).
**Метод:** статический аудит кода, 6 параллельных зон-аудиторов + проверка гейтов + повторная верификация ~50 находок по исходникам.
**Гейты на момент аудита:** `go build ./...`, `go vet ./...`, `go test ./...` — все зелёные.
**Охват:** 363 Go-файла (включая тесты). Детально аудированы: `a2a`, `mcpserver`, `mcp`, `network`, `internal` (httpx/sse/uuid), `live`, `contrib`, `toolpacks`, `tools`, `files`, `acp`, `agui`, `a2ui`, `mcpui`, `tui`, `agent`, `events`, `stream`, `context`, `hitl`, `middleware`, `knowledge`, `policies`, `task`, `compact`, `observers`, `watch`, `response`, `plugin`, `cmd`, `examples`, `install.sh`, CI, git-история.

## Словарь терминов

- **RCE** (remote code execution) — выполнение произвольного кода/команд на машине.
- **Prompt injection** — модель выполняет инструкции, спрятанные в тексте, который она читает (веб-страница, файл, вывод инструмента).
- **SSRF** — атакующий заставляет сервер слать запросы на выбранный им адрес (например, во внутреннюю сеть).
- **IDOR** — доступ к чужим данным по угадываемому/утёкшему идентификатору.
- **TOCTOU** — проверка и действие разнесены во времени; между ними объект можно подменить.
- **ANSI/OSC-инъекция** — спецпоследовательности в тексте, которые терминал исполняет (OSC 52 — запись в буфер обмена; чтение поддерживается редкими терминалами).
- **Fail open / fail closed** — при сбое механизм пропускает (опасно) или блокирует (безопасно).
- **CSWSH** (cross-site WebSocket hijacking) — чужая веб-страница открывает WebSocket на localhost из браузера жертвы.

**Общий вывод.** Код дисциплинированный: параметризованный SQL, fail-closed HITL, crypto/rand ID, лимиты тел 8 МиБ, `InsecureSkipVerify` нигде нет, гонки в core-путях в основном закрыты. Слабые места трёх видов:

1. **Реальные дефекты** (чинить первыми): гонка-паника в `LocalLink`, push-вебхук с дефолтом «принимать любой URL» и уходящей наружу историей, наследование `os.Environ()` дочерними процессами, динамический подагент без middleware родителя, неограниченный taskstore, отсутствие стоп-крана цикла инструментов.

Обязательное условие безопасного использования — Approval + белый список env, и честный doc-контракт.
3. **Риск деплоя**: ни один HTTP/WS-хендлер не несёт встроенной аутентификации. Для библиотеки это нормальный Go-подход (обёртка `authMiddleware(handler)`), но ни хука-опции, ни документального требования «не-loopback только за auth-прокси» нет. До любого не-loopback экспоза — обязательный минимум: auth-хуки + Origin/Host.

# Риски by-design [DESIGN] — возможности, не дефекты кода

### C-1. [DESIGN, Critical-риск] Shell-инструмент исполняет строку, полностью контролируемую LLM
- **Где:** `toolpacks/shell.go:186-188`
  ```go
  return []string{"cmd", "/c", command}   // Windows
  return []string{"sh", "-c", command}    // Unix
  ```
- **Что:** вся строка `command` (аргумент инструмента, т.е. выход LLM) уходит интерпретатору оболочки как есть. Блок-лист `WithShellBlockPatterns` (`shell.go:172-178`) — advisory-фильтр, не граница безопасности (сам код это признаёт); обходится кодированием, `$(...)`, переменными, `%VAR%`.
- **Риск при использовании:** инструмент подключается сознательно; но в связке с любым недоверенным входом (search, чтение файлов, SKILL.md) одна prompt injection → произвольные команды от имени пользователя процесса. Вместе с H-6 (`os.Environ()`) — `env` + `curl` = кража всех ключей. Изоляции нет: реальный temp-каталог, сеть и ФС не ограничены. В Python-паритете изоляция существовала (Docker-бэкенд) и в порт пока не вернулась.
- **Действие:** честный doc-контракт («executes arbitrary code by design; NOT a security boundary; require Approval»); обязательное одобрение при подключении; в план — песочница.

### C-2. [DESIGN, Critical-риск] Coderunner без изоляции; описание инструмента ложно называет среду «sandboxed»
- **Где:** `toolpacks/coderunner.go:165` (описание «Execute code in a sandboxed environment»), `:226-253` (исполнение: `python -c`, `bash -c`, `node <file>` в локальном каталоге).
- **Что:** песочницы не существует, поэтому «sandbox escape» тут неправильный термин. Суть в двух вещах: (а) код исполняется на хосте без изоляции ФС/сети/памяти (есть только таймаут 60 с, лимит вывода и ограничение языков) — это by-design возможность; (б) **описание инструмента дезинформирует модель** («sandboxed» → модель считает среду безопасной и одноразовой) — это реальный дефект контракта, чинить обязательно.
- **Риск при использовании:** аналогично C-1; python-код читает окружение с ключами (H-6) и ходит в сеть.
- **Действие:** убрать «sandboxed» из описания; предупреждение в doc-контракте; изоляция — в план (возврат из Python-паритета).

# High

### H-1. [DEPLOY, High при не-loopback] Сервер a2a не имеет аутентификации; встроенного хука нет
- **Где:** `a2a/server.go:32-77` (в `ServerConfig` нет полей проверки), `:139` (ServeHTTP), `:208-229` (диспетчер); `a2a/security.go:12-13` — схемы в карточке «pure card metadata with no crypto», сервер никогда не сверяет предъявленный токен.
- **Уточнение v2:** защититься можно сегодня — обернуть `http.Handler` своим auth-middleware (обычная Go-практика). Проблема в отсутствии встроенной точки подключения и документального требования.
- **Последствие при экспозе:** `message/send` → LLM-расход и инструменты агента; `tasks/get` → чужая история; `tasks/cancel`; push-config → SSRF (H-2).
- **Рекомендация:** хук `Authorize` в `ServerConfig` + док «не-loopback только за auth-прокси».

### H-2. [BUG, High] Push-вебхук: дефолт «принимать любой URL», наружу уходит вся история задачи, клиент без таймаута следует редиректам
- **Где:** `a2a/push.go:73` (`PushURLValidator`, nil = принимать всё), `:253` (валидация опциональна), `:160-175`:
  ```go
  req, _ := http.NewRequestWithContext(ctx, http.MethodPost, cfg.URL, bytes.NewReader(body))
  resp, err := http.DefaultClient.Do(req)   // Timeout=0, редиректы до 10
  ```
- **Что:** URL приходит от клиента; тело — весь `Task` с историей переписки (контролируемой атакующим). Задачу атакующий создаёт сам одним `message/send`.
- **Последствие:** SSRF-примитив (POST с контролируемым телом на `169.254.169.254`, `localhost`, внутренние адреса); эксфильтрация чужой истории при известном taskID (M-1); обход allowlist через редирект.
- **Рекомендация:** дефолтный валидатор (запрет приватных/loopback/link-local IP, https в проде), `CheckRedirect` без смены хоста, таймаут (M-3), в тело — только статус и идентификаторы.

### H-3. [DEPLOY, High при не-loopback] mcpserver HTTP-транспорт без аутентификации
- **Где:** `mcpserver/http.go:26-38` (диспетчеризация по методу без проверок); `mcpserver/server.go:7-12` — OAuth deferred (D-056). Как и H-1, закрывается обёрткой; встроенного хука нет.
- **Рекомендация:** хук авторизации в конфиг; гейт на `initialize`/`tools/*`; док «loopback или auth-прокси».

### H-4. [BUG, High] Неограниченный рост MemoryTaskStore (удалённый OOM); уточнение про taskLocks
- **Где:** `a2a/taskstore.go:89-104` (`Save` только пишет; `Delete` сервером не вызывается); `a2a/server.go:263-273` — `newTask` принимает клиентский `TaskID`.
- **Уточнение v2:** рост `taskLocks` срабатывает только для сторов **без** `TaskUpdater` (`a2a/server.go:449-460`); дефолтный `MemoryTaskStore` реализует `Update`, поэтому в дефолтной конфигурации течёт сам стор (до 8 МиБ истории на каждый уникальный клиентский taskId), а не map локов.
- **Рекомендация:** лимит задач с eviction (LRU/TTL); не принимать клиентские taskID при создании.

### H-6. [BUG, High] Дочерним процессам shell/code/terminal передаётся всё окружение родителя
- **Где:** `toolpacks/exec.go:52` — `cmd.Env = os.Environ()`; `acp/terminal.go:110` — то же.
- **Последствие:** одна команда `env`/`printenv` отдаёт модели `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` и всё остальное; далее `curl` на сервер атакующего. Замыкает C-1/C-2 в полный цикл кражи ключей. Дешёвый фикс.
- **Рекомендация:** белый список переменных (PATH, TEMP, HOME, SystemRoot); секреты — точечно через опции.

### H-7. [BUG + PARITY, High] Динамический подагент исполняет инструменты пула без middleware родителя (подтверждение человеком — один раз)
- **Где:** `toolpacks/dynamic.go:151` — `opts := []agent.Option{agent.WithConfig(f.cfg)}`; далее `spec.ToAgent(f.pool, opts...)` (`spec/spec.go:122-123`), `agent/run.go:199` берёт middleware только из opts самого агента.
- **Уточнение v2:** формулировка «человек видит только имя и objective» была неверна. Аргументы `create_and_run_agent` — JSON с полным `spec` (`name`, `prompt`, `tool_names`, `response_schema`, `toolpacks/dynamic.go:118-124`), и approval строит вопрос из `ev.Arguments` (`middleware/approval.go:65-68`) — то есть человек видит список инструментов, но в виде сырого JSON, и **не видит ни одного последующего вызова** child-агента.
- **Паритет:** Python делает то же (`ag2/ag2/tools/dynamic/handler.py:32-35` — `spec.to_agent(available_tools=pool, config=config)` без middleware). Это паритетное, но опасное поведение.
- **Последствие:** «агент + Approval + пул с run_shell_command» → одно одобрение создания = неограниченный shell без дальнейших вопросов.
- **Рекомендация:** прокидывать middleware-фабрики родителя в opts child-агента (потребует AGO-DEVIATION + DECISIONS, т.к. ломает паритет); либо запретить требующим одобрения инструментам попадать в пул динамической фабрики.

### H-11. [PARITY, High] Бесконечный цикл инструментов без стоп-условия
- **Где:** `agent/turn.go:100` — `for len(resp.ToolCalls.Calls) > 0 && !resp.ResponseForce {`.
- **Уточнение v2:** это паритет — в Python тот же неограниченный цикл (`ag2/ag2/agent.py:1823-1824`, `while True: if message.tool_calls and not response_force`). Не регрессия порта, но риск тот же: враждебный tool-результат с инструкцией «продолжай вызывать инструменты» крутит платные LLM-вызовы бесконечно; остановит только внешний Halt или отмена вызывающим.
- **Рекомендация:** либо `WithMaxToolRounds` (с AGO-DEVIATION), либо зафиксировать в документации обязательность внешнего лимитера.

### M-9. [BUG, повышено до High в v2] Гонка push/Close в LocalLink: паника «send on closed channel»
- **Где:** `network/transport/link.go:173-178` (push после проверки `done`, без lock) против `:228-229` (`close(c.inbox)`).
- **Что:** между проверкой и отправкой `Close` закрывает канал — отправка в закрытый канал паникует. Паника в библиотечном коде рушит весь процесс (нарушение «No panics in library code»). Триггер — конкурентный Close при живом трафике; раса реальная, воспроизводится конкурентным использованием.
- **Рекомендация:** не закрывать `inbox`, работать через `select` с `done`; либо мьютекс на push/close. Дешёвый фикс — делать первым.

# Medium

## Сеть и доступ

**M-1. [BUG] AuthZ/IDOR — изоляции задач нет: знание taskID = полный контроль; клиент может навязывать свои taskID**
`a2a/server.go:263-285` (`loadOrCreateTask` подхватывает любой существующий ID без проверки владельца; клиентский `msg.TaskID` выигрывает), `:600-609` (`tasks/get` отдаёт историю по ID), `a2a/push.go:305-342`. Серверные ID — UUID v4 (неугадываемы), но клиентские разрешены; `contextId` нигде не сверяется. Атакующий с утёкшим taskID читает переписку, отменяет задачу и перехватывает HITL-клапан (continuation с поддельными tool-results на чужую parked-задачу). → Модель владения (секрет на задачу/контекст), сверка contextId, запрет клиентских taskID.

**M-2. [BUG] Гонка «первого коммита» задачи; воскрешение удалённых**
`a2a/server.go:520-527`: ветка «задачи нет» делает `Save` вне per-task блокировки; два параллельных `message/send` с одним новым ID → last-write-wins, оба клиента получают успех. Плюс `apply(task)` работает с устаревшей копией — удалённая задача воскрешается со старым статусом. → Первый коммит под `lockTask`/upsert; перечитать запись перед `Save`.

**M-3. [BUG] Push-доставка: горутина на конфиг без таймаута и лимита параллелизма, ошибки проглатываются**
`a2a/push.go:361-366` (`go func` с `WithoutCancel`, `_ = sender(...)`), `:175` (`http.DefaultClient`, Timeout=0). Медленный/злой вебхук вешает горутину навсегда; отказы доставки невидимы. → `WithTimeout(WithoutCancel(ctx), 30s)`, семафор, лог ошибок.

**M-4. [BUG] Secrets — push-конфиги с токенами возвращаются по get/list любому знающему taskID**
`a2a/push.go:105-123` (`Get`/`List` отдают `Token`, `Authentication.Credentials`), `:283-290`. → Маскировать credentials в ответах; модель владения (M-1).

**M-5. [BUG] Клиент a2a: нет дефолтного таймаута и лимита при загрузке agent card**
`a2a/client.go:76` (`&http.Client{}` — Timeout 0), `:100` (`Decode` без `LimitReader`; в `call()` лимит 8 МиБ есть, в карточке — нет). → Дефолтный Timeout + `io.LimitReader`.

**M-6. [BUG] mcpserver: GET SSE-стрим держится бесконечно, лимита соединений нет**
`mcpserver/http.go:103` (`<-r.Context().Done()`). Серия GET исчерпывает FD/горутины. → Лимит одновременных стримов; idle-таймаут на уровне `http.Server`.

**M-7. [DEPLOY] Хаб доверяет заявленному SenderID; `Passport.Auth` не проверяется ничем**
`network/identity.go:37` («validated by nothing in this subset»), `network/hub.go:828-833`. Весь контроль доступа вычисляется от имени, которое задаёт отправитель. В одном процессе — по дизайну; любой сетевой мост или скомпрометированный код пишет от имени любого агента. → Зафиксировать в ARCHITECTURE.md «хаб = один trust domain»; для сетевых сценариев подпись/токен на конверт или маппинг «линк → разрешённый AgentID».

**M-8. [BUG, сужено в v2] IDOR в клиентских инструментах: `close` чужого канала и `tasks scope=all`**
Реальные дефекты (после уточнения): `network/clienttools.go:260` — `close` закрывает **любой** канал без проверки участника; `:352-355` — `tasks list scope=all` отдаёт метаданные всех задач (`owner=""`); `channels info` при этом участие проверяет. Частично подтверждённые в v1 «чтение чужой переписки» — **не подтверждается**: `search` (`:481`) и `quote` (`:527`) фильтруют через `VisibleTo`; адресные сообщения чужого канала недоступны, broadcast виден всем — это задокументированная семантика (см. I-11). → В `close` и `scope=all` требовать участие/inbound-правило вызывающего.

**M-10. [BUG] SSE-парсер: неограниченный рост накопленного события**
`internal/sse/sse.go:60` — строка ограничена 8 МиБ, но число `data:`-строк внутри события не ограничено. Злой/сломанный LLM-эндпоинт шлёт бесконечные `data:` без пустой строки → OOM. Касается всех стримящихся клиентов. → Кап суммарного размера события.

**M-11. [BUG] Неограниченное чтение тела ответа**
`internal/httpx/httpx.go:159` (`io.ReadAll(resp.Body)`), `live/openai.go:174,284` (аудио-байты). Гигантский ответ → OOM. → `io.LimitReader` с настраиваемым капом.

Все перечисленные поправки сверены по исходникам и подтверждены:

4. **H-7** — исправлена формулировка: человек видит сериализованный spec (включая `tool_names`, `dynamic.go:118-124`), но не последующие вызовы child-агента; добавлена пометка паритета с Python (`handler.py:32-35`).
5. **M-8** — сужено: `search`/`quote` фильтруют `VisibleTo` (`clienttools.go:481,527`); реальные дефекты — `close` без участника (`:260`) и `tasks scope=all` (`:352-355`); broadcast-видимость — задокументированная семантика (→ I-11).
6. **H-8/H-9** — понижены до Medium: ACP stdio-only (`serve.go:305-306`), агент — локальный подпроцесс того же пользователя; не privilege escalation. Пометка «станет High при сетевом транспорте/изоляции». Рекомендации сохранены как defense-in-depth.
7. **H-10** — понижено до Medium; OSC 52 — в основном запись в clipboard (чтение — редкие терминалы).
8. **C-2** — переименовано из «Sandbox Escape» (песочницы не существует) в «misleading sandbox claim + отсутствие изоляции»; C-1/C-2 перенесены в категорию «риски by-design».
