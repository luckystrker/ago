## 2026-11-23 — модель недоступна на одном провайдере: искать тот же уровень у другого, а не предлагать замену

- **Реакция (дословно):** «на Claude code запускай еблан»
- **Где:** тред `thr_gn9kthfwfi`, сессия синка AG2 v1.3.4; вопрос был «Opus 5.5 medium недоступен без пополнения баланса — на чём запускать нарезку тикетов?» с вариантами «пополнить», «я сам нарежу», «Haiku 5.5».
- **Что агент сделал:** попытался запустить субагента на `opencode/claude-opus-5-5#medium`, получил «Insufficient balance», проверил модели через инструмент моделей OpenCode (там только провайдеры `opencode` и `opencode-go`), после отказа предложил владельцу три варианта — пополнить кредиты, нарезать самому или взять Haiku по подписке — вместо того, чтобы проверить провайдеры самого bb (`bb provider list`, `bb provider models <id>`), где `claude-code` даёт `claude-opus-5-5` по подписке.
- **Чего хотел владелец:** просил Opus 5.5 medium — значит запустить именно его; недоступность на одном провайдере не повод менять модель, надо найти того же Opus у другого провайдера harness'а (в bb это `claude-code`, запуск тредом `bb thread spawn --provider claude-code --model claude-opus-5-5 --reasoning-level medium`).
- **Тип:** ошибка процесса (не проверил все пути до вопроса владельцу) + вкус (Opus как требование, не как пожелание).
- **Повтор?** Первая запись.
- **Предлагаемое принуждение:** хук/чек-лист шага перед вопросом владельцу — «если запрошенная модель недоступна, сначала перебрать все провайдеры обоих каталогов (`opencode models` и `bb provider list/models`) и только потом спрашивать». Сильнее — правило в скилле `teamlead`/`model-bench`: таблица «модель → провайдеры bb», по которой выбор идёт по имени модели, а не по первому провайдеру. Слово в `AGENTS.md` — только если правило не приживётся.
