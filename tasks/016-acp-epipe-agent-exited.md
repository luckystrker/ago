## Что сделать
Найдено при проверке 013 (проверяющий thr_thph8mu834; воспроизведено примерно в 1% прогонов: 2 из 200 при `-count=200`).
`acp` `TestProviderStartupFailures/exits_during_the_handshake` иногда падает с
`err = acp: write: write |1: broken pipe, want a transport error wrapping ErrAgentExited`. Агент завершается
сразу, клиент пишет `initialize` в уже закрытый pipe и получает EPIPE раньше, чем замечает выход процесса.
Это гонка в продуктовом коде, а не только флейк теста: пользователь видит «broken pipe» вместо «агент завершился».
Риск 2×3=6. Запись в `docs/known-issues.md` сделал тикет 013, этот тикет её закрывает.

Шаги (red-first):
1. Детерминированный тест: фейковый агент закрывает stdin/выходит **до** записи `initialize` (без снов, порядок задаётся
   каналами/пайпами) → сейчас ошибка без `ErrAgentExited` (красный стабильно, а не в 1% случаев).
2. Правка в транспорте клиента ACP: ошибка записи (`syscall.EPIPE`/`os.ErrClosed`/`io.ErrClosedPipe`), когда процесс агента
   завершился или вот-вот завершится, оборачивается в `ErrAgentExited` (`%w`, исходная ошибка тоже доступна через `errors.Is`).
   Ждать завершения процесса — с ограничением по времени, не бесконечно.
3. `go test -count=500 -p 1 -run TestProviderStartupFailures ./acp/` — 500/500.
4. Строку в `docs/known-issues.md` перенести в исправленное с коммитом.
