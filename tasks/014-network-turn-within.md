## Что сделать
Upstream `2aa5bfaf` (`git -C <ag2> show 2aa5bfaf`; идеи сценарных тестов — `test_bridge_drives_workflow.py`,
`test_hub_client_wire_results.py` из `c81e43f2`). В Python `WorkflowAdapter`/`DiscussionAdapter` объявляли
`turn_within`, но оценщика не было — зависший workflow никогда не закрывался. У нас ожидания выброшены сознательно,
комментарии теперь устарели: `network/adapters.go:484-486` (Discussion) и `:497-498` (Workflow), запись D-101.

**Что уже есть:** `ExpectedTurn`/`ExpectedNext()` (`network/turns.go`); оценщики `acks_within`/`reply_within`/`max_silence`;
снимок состояния и WAL под локом хаба (`sweepChannel`, `network/expectations.go:383`) — «чтение под одним локом» сделано.
**Чего нет:** `TurnWithinEvaluator`, `warn`-обработчика, `expectedTurn` в `ExpectationContext` (`:40`), дедупа по ходу:
сейчас ключ `"%d|%s|%s"` = `idx|kind|violator` (`:421`) — участник срабатывает один раз на всю жизнь канала.

Шаги (red-first, сначала сценарный тест «зависший workflow»):
1. **Сценарий.** Workflow-канал, ход передан участнику B, B молчит дольше окна → сейчас нарушения нет (красный);
   после — `turn_within` срабатывает на B, обработчик из манифеста выполняется (закрытие канала / событие).
2. **`ExpectationContext.ExpectedTurn`** — из адаптера канала (аддитивное поле).
3. **`TurnWithinEvaluator`**: окно отсчитывается от конверта, передавшего ход; для первого хода — от `EV_CHANNEL_OPENED`.
   Регистрация в наборе оценщиков по умолчанию.
4. **`warn`-обработчик**: шлёт `EV_EXPECTATION_VIOLATED` **только нарушителю**. Регистрация в хабе (`network/hub.go:382`).
5. **Дедуп с учётом хода**: ключ `(expectation, violator, turn)` — тест: один участник нарушает на ходе 1 и снова на
   ходе 3 → два срабатывания; повторный свип на том же ходе → одно. Учти персистентность ключа (комментарий
   `network/listener.go:37`): если ключ где-то пишется в WAL/аудит, форма должна читаться и старая.
6. **Аудит нарушений без обработчика** (`on_violation` неизвестен — сейчас `continue`, `:418`; discussion `hide`): нарушение
   видно в аудите. Сверь, ломает ли это «silently ignored (Python parity)» — следуй новому Python.
7. **Манифесты**: `DiscussionAdapter`/`WorkflowAdapter.DefaultManifest` несут оба `turn_within` с дефолтами Python;
   оба `AGO-DEVIATION`-комментария удалить.
8. **Документы:** `docs/DECISIONS.md` **D-134** — отменяет пункт D-101 про `turn_within` (D-101 не редактировать, сослаться);
   `docs/MIGRATION.md` «AG2 v1.3.4 sync»; `docs/PORT_STATUS.md` — строка `network/`.

Инварианты (property-тест, не TLA+: новой конкурентности нет, всё под существующим локом `sweepChannel`; если правка
задевает порядок WAL/доставки из `spec/tla/Hub*.tla` — стоп, к тимлиду): (И1) нарушение на паре (участник, ход) срабатывает
