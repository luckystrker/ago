> **human: required** — тикет меняет границу безопасности: что именно разрешает чужому ACP-агенту одно «да» человека
> (разовое действие или разрешение на всю сессию). В `done` переводит только владелец.

## Что сделать
Три коммита одной волны upstream (`git -C <ag2> show 364c0ce5`, `d115d14d`, `47af7402`; контракт — ADR 0039 в
`df85d499`). Один тикет, потому что тип выбора проходит сквозняком `events` → `agui` → `acp`: по отдельности ни
один кусок не закрывает дырку и не проверяется.

**Дефект (снят при разборе синка).** `acp/bridge.go` `permissionAnswer` (~стр. 773): политика
`Permission(toolCall, input) == true` → берётся **первая** опция `allow_once|allow_always` **в порядке агента**.
Gemini CLI ставит `allow_always` первой → одно «да» на `git status` даёт разрешение на все `git`-команды сессии.
Serve-роль (`acp/serve.go`) не больна — она сама синтезирует `allow_once`/`reject_once`; трогать её не нужно.

Шаги, каждый red-first:
1. **Регрессия дырки.** Фейковый ACP-агент шлёт `session/request_permission` с опциями в порядке
   `[allow_always, allow_once, reject_once]`, политика отвечает «да». Сейчас в ответе на проводе `optionId`
   `allow_always`-опции — тест краснеет. После — `allow_once`. То же для порядка без `allow_once`: «да» → отказ
   (reject-опция агента или `cancelled`), а не `allow_always`. Отказ (`deny`) предпочитает `reject_once` независимо от порядка.
2. **`events`.** `events.ToolApprovalRequest` (`events/human.go:25`) — аддитивно `Choices []ApprovalChoice`
   (`json:"choices,omitempty"`), тип `ApprovalChoice{Value, Label}`; тип ответа-выбора (аналог `ApprovalChoiceMessage`) —
   отдельный от `HumanMessage`, чтобы выбор и слово не смешивались. JSON-теги — имена Python. Регистрация в
   `events/marshal.go` + круговой тест Marshal/Unmarshal.
3. **`acp` bridge.** Запрос прав уходит человеку с опциями агента (`option_id`, `name`, `kind` + `kind`/`locations`/
   `raw_input` вызова) как `Choices`. Разбор ответа: **сначала слова** (`yes`/`y`/`1` → one-time allow или отказ, если его
   нет; `always` → remembered; прочее → отказ), выбор — **только** по id предложенных опций. Как это ложится на текущую
   политику `Bridge.Permission func(...) bool` — реши и опиши в D-132; булева политика остаётся и значит «one-time».
4. **`Decision.Allowed()`** (`acp/acp.go:686`) сейчас считает разрешением любой id кроме `"reject"`, то есть и
   `reject_once`. Выводить из `kind` выбранной опции. Тест: выбранная `reject_once`-опция → `Allowed() == false`.
5. **`agui`.** `approvalSchema` (`agui/interrupts.go:62`) — третья ветка `{"choice": value}` рядом с `string|boolean`,
   отрисовка `choices` в схеме ответа; `answerFrom` (`:162`) возвращает типизированный ответ (слово | bool | выбор),
   а не строку. Строка, совпавшая со значением выбора, остаётся **словом**. Невалидный выбор / не предложенное
   значение → отказ с `PAYLOAD_REFUSED`. Учти существующее отступление D-065 (bool транслируется для любого interrupt) —
   не ломать его для простых вопросов.
6. **Столкновения (обязательные тесты):** reject-опция с id `"y"` выбирается выбором и **не** выбирается словом;
   allow-опция с id `"n"`: кнопка «отказать» (bool false) её не выбирает.
7. **Документы:** `docs/DECISIONS.md` **D-132** — аналог ADR 0039 (контракт: слова не расширяются, выбор только по id,
   `{"choice": ...}` на проводе, `Allowed()` по `kind`). `docs/MIGRATION.md` — раздел «AG2 v1.3.4 sync» (заведи, если его нет).
   `docs/PORT_STATUS.md` — строки `acp/`, `agui/`.

## Поведенческое изменение / совместимость
- «Да» человека/политики больше никогда не выбирает `allow_always`: пользователи, полагавшиеся на «одно да на сессию»,
  будут получать запрос на каждую команду. Это намеренно — строка в MIGRATION.
- `Decision.Allowed()` меняет ответ для `reject_once`/`reject_always` — **breaking** по смыслу, строка в MIGRATION.
- `ToolApprovalRequest.Choices`, новый тип ответа, ветка `{"choice": ...}` — аддитивны; старые клиенты AG-UI, шлющие
  string/bool, работают как раньше.
- Записи: D-132 (обязательно), MIGRATION «AG2 v1.3.4 sync» (обязательно).
